# รูปแบบ JSON และวงจรเผยแพร่ Q&A

## Question

JSON ต้องมีฟิลด์อะไร ใช้รหัส Q&A อย่างไร และเมื่อซ้ำ/ผิดรูปแบบ/นำเข้าซ้ำให้เพิ่ม แทนที่ หรือปฏิเสธแบบใด? แอดมินตรวจเผยแพร่เป็นรายรายการหรือเป็นชุด การแก้ไขและลบเริ่มมีผลต่อบอตเมื่อใด และการเตรียมข้อมูลที่ล้มเหลวแสดงอย่างไร?

## Comments

### Resolution — ผู้ใช้มอบหมายให้ออกแบบ JSON สำหรับเพิ่มข้อมูลใน vector database

#### รูปแบบนำเข้า

ไฟล์ UTF-8 JSON เป็น array ของ Q&A แต่ละรายการมี `question` และ `answer` เป็น string ที่ไม่ว่างหลัง trim เท่านั้น ไม่ต้องกรอก vectors, business_id, collection หรือรหัสรายการ ระบบกำหนดรหัสภายในเอง ดู [ไฟล์ตัวอย่าง](../assets/qa-import.example.json)

```json
[
  {
    "question": "ร้านเปิดกี่โมง?",
    "answer": "เปิดทุกวัน เวลา 09:00–18:00 น."
  }
]
```

- แอดมินเลือกธุรกิจในหน้าจัดการก่อนนำเข้า ฝั่งระบบกำหนดขอบเขตธุรกิจให้เอง ไม่เชื่อค่ากำหนดธุรกิจจากไฟล์
- ไม่บังคับภาษา และไม่ต้องเพิ่ม metadata ที่ยังไม่มีการใช้งานใน MVP
- JSON นี้เป็นข้อมูลต้นทางสำหรับเตรียมความรู้ ไม่ผูกกับรูปแบบ API ของ vector database รายใด

#### ตรวจสอบและข้อมูลซ้ำ

- ตรวจทั้งไฟล์ก่อนสร้าง draft ถ้า JSON ผิดรูปแบบ ไม่ใช่ array, array ว่าง, มีฟิลด์นอกเหนือที่กำหนด หรือ field ไม่ถูกต้อง ให้ปฏิเสธทั้งไฟล์พร้อมหมายเลขรายการและเหตุผล ไม่เขียนข้อมูลบางส่วนจากไฟล์ที่ validation ไม่ผ่าน
- เปรียบเทียบข้อมูลหลัง trim หัวท้ายและปรับ Unicode เป็น NFC โดยไม่เปลี่ยนตัวพิมพ์หรือช่องว่างภายในข้อความ
- question และ answer เหมือนเดิมทั้งคู่ในธุรกิจเดียวกัน: ข้าม ทั้งภายในไฟล์และเมื่อเทียบกับรายการ draft/เผยแพร่ที่ยังไม่ถูกลบ การนำเข้าไฟล์เดิมซ้ำไม่เพิ่มรายการซ้ำ
- question เหมือนเดิมแต่ answer ต่างกัน: แจ้ง conflict และให้แก้รายการเดิมผ่านหน้าจัดการหรือแก้ไฟล์ ไม่เขียนทับเงียบ ๆ ถือเป็น validation failure ของไฟล์
- คำถามคล้ายกันแต่ข้อความต่างกันยังเพิ่มได้ การจัดกลุ่มตามความหมายเป็นประเด็น feedback loop แยกต่างหาก
- การนำเข้าเป็นการเพิ่มเท่านั้น ไม่มีการลบรายการที่ไม่ได้อยู่ในไฟล์ และไม่มีการแทนที่ทั้ง collection

#### เผยแพร่และการสร้าง vectors

- ทั้งการกรอกเองและนำเข้าสร้าง draft ให้แอดมินตรวจ จากนั้นกดเผยแพร่เป็นรายรายการหรือเลือกหลายรายการได้ ไม่มีขั้นตอนอนุมัติจากบุคคลที่สอง
- ระบบใช้ sentence-transformers สร้าง embedding จาก `question` ตามวิธี encode ของโมเดลที่เลือก และเก็บ `answer` เป็นข้อความสำหรับส่งประกอบคำตอบ พร้อมรหัสธุรกิจ/รายการ/รุ่นข้อมูลที่ระบบกำหนด
- บอตใช้เฉพาะรายการที่เผยแพร่และสร้างดัชนีสำเร็จในธุรกิจปัจจุบัน ห้ามค้นข้ามธุรกิจ
- รูปแบบ collection จริงจะตัดสินเมื่อเลือกฐานข้อมูลใน [ชุดเทคโนโลยีและค่าเริ่มต้นพร้อมติดตั้ง](08-runtime-defaults.md); รูปแบบไฟล์นำเข้าไม่ต้องเปลี่ยนตาม
- แสดงผลรายรายการ: สำเร็จ ข้ามซ้ำ หรือล้มเหลว พร้อมเหตุผล รายการที่สร้างดัชนีล้มเหลวยังไม่เผยแพร่และลองใหม่ได้ การเผยแพร่เป็นชุดอาจสำเร็จบางรายการและต้องรายงานตรงตามผลจริง
- แก้ไข Q&A ที่เผยแพร่แล้ว: เก็บการแก้เป็น draft รุ่นใหม่ รุ่นเดิมยังใช้ได้จนแอดมินเผยแพร่รุ่นใหม่สำเร็จ จากนั้นใช้เฉพาะรุ่นใหม่ ไม่ตอบจาก vectors ของรุ่นเก่า
- ลบ Q&A: ตัดออกจากการค้นใหม่ทันทีเมื่อระบบยืนยันการลบ แม้งานลบ vectors ยังไม่เสร็จ ต้องตรวจสถานะรายการก่อนใช้ผลค้นหา บทสนทนาหรือคำขอที่ดำเนินการไปแล้วไม่ถูกย้อนแก้
- ข้อมูล Q&A ต้นฉบับเก็บในเครื่องแยกจากดัชนีเพื่อสร้าง embeddings ใหม่ได้เมื่อเปลี่ยนโมเดล
