# 08: ตรวจรับและเตรียมเผยแพร่ MVP

**What to build:** ผู้ใช้ใหม่ทำตามคู่มือจากการติดตั้งสะอาดจนบอตตอบคำถามและแอดมินนำ feedback ไปเพิ่มความรู้ได้ พร้อมเอกสารสำหรับเผยแพร่โครงการบน GitHub

**Blocked by:** 01: ติดตั้งระบบและจัดการธุรกิจ, 02: เพิ่ม Q&A แล้วถามบอตได้จริง, 03: แก้ไขและลบความรู้ที่เผยแพร่แล้ว, 04: นำเข้า Q&A จาก JSON, 05: เก็บบทสนทนาและ feedback, 06: เห็นคำถามยอดนิยมและเติมช่องว่างความรู้, 07: เปลี่ยนโมเดลผ่าน config.

**Status:** ready-for-agent

- [ ] ทดสอบเส้นทางติดตั้ง → admin สร้างธุรกิจ → กรอก/นำเข้า Q&A → เผยแพร่ → แชต → feedback → เติมความรู้ → ถามใหม่
- [ ] ตรวจการแยกธุรกิจ สิทธิ์ admin การเข้าถึงบทสนทนา และการไม่ใช้ความรู้ที่ลบหรือยังไม่เผยแพร่
- [ ] ตรวจ restart แล้วข้อมูลยังอยู่ รวมถึงบริการภายนอกล้มเหลวและการเปลี่ยนโมเดล/reindex
- [ ] มีคู่มือติดตั้ง CPU/Docker Compose การตั้งค่า OpenRouter การดาวน์โหลดโมเดล นำเข้า JSON และเปลี่ยนโมเดล พร้อมตัวอย่างข้อมูลที่ไม่มี secrets
- [ ] ระบุผลทดสอบ Windows/macOS/Linux ตามที่ทดลองจริง แยกเป้าหมายรองรับออกจากแพลตฟอร์มที่ยืนยันแล้ว และไม่อ้างความจุไม่จำกัด
- [ ] ตรวจว่าไม่มีประเด็นผลิตภัณฑ์ที่ยังไม่ตัดสินใจค้างอยู่ก่อนประกาศ MVP พร้อมใช้; การตรวจรับเชื่อมกับเกณฑ์ในแต่ละงาน
- [ ] เตรียมข้อมูลสิทธิ์ใช้งานโครงการและโมเดลให้ชัดก่อนเผยแพร่สาธารณะ โดยไม่สมมติ license และไม่ push/publish repository ใน ticket นี้

## รายละเอียดที่ต้องสรุปก่อนดำเนินงานส่วนที่เกี่ยวข้อง

สรุปเกณฑ์รับมอบจากประเด็นเกณฑ์รับมอบ MVP และขอบเขตสเปกฉบับพร้อมพัฒนา รวมถึงภาษาของ UI ที่ยังไม่ได้เลือก; งานนี้เตรียมเผยแพร่ ไม่ถือว่าได้รับคำสั่งให้สร้าง GitHub repo หรือ push แล้ว
